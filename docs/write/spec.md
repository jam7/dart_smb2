## 仕様一覧

### S-01: 名前を押さえてから書き始める (実現する要件: R-01, R-02)
- 挙動: `createNew(path)` は共有上に `path` のファイルを作り、そこへ書くための
  writer を返す。**返った時点でファイルは既に存在し、長さは 0**。作れなかった
  ときは writer を返さず例外を投げる
- 境界条件・エラー時:
  - **同じ名前が既にある**: 例外。**そのファイルの長さと中身は変わらない**
  - **同じ名前のディレクトリがある**: 例外。ディレクトリは残る
  - **親ディレクトリが無い**: 例外。ディレクトリは作らない
  - **書き込み権限が無い**: 例外。権限の問題であることが例外から分かる
  - どの失敗でも、**共有上に新しいものは何も作られない**
- 受入条件 (テスト可能な形で):
  - [ ] 無い名前に `createNew` → 成功し、その直後に一覧すると**長さ 0 の
        ファイルが 1 つ増えている**
  - [ ] 既にある名前に `createNew` → 例外。**その前後でファイルの長さと中身が
        一致する** (長さだけでなく中身も読み直して比べる)
  - [ ] 存在しない親を持つパスに `createNew` → 例外。**親も子も作られていない**
  - [ ] 失敗したとき、一覧の件数が呼び出し前と等しい

### S-02: 渡したバイト列が、渡した順にそのまま並ぶ (実現する要件: R-01)
- 挙動: `write(bytes)` は現在位置に `bytes` を置き、位置をその長さだけ進める。
  `close()` の後に同じパスを読み直すと、**渡したバイト列を渡した順に連結した
  ものと 1 バイト残らず一致する**
- 境界条件・エラー時:
  - **1 度も `write` せずに `close`**: 長さ 0 のファイルが残る (エラーではない)
  - **長さ 0 のバイト列を `write`**: 位置は動かず、結果も変わらない
  - **`close` の後に `write`**: 例外。ファイルは `close` した時点のまま
  - **`close` を 2 度**: 2 度目は何もしない (例外にしない)
- 受入条件:
  - [ ] 3 回に分けて書いた 3 つのバイト列 → 読み直すと**連結と完全一致**し、
        長さも合計と一致する
  - [ ] 1 度も書かずに `close` → **長さ 0**。ファイルは存在する
  - [ ] 長さ 0 のバイト列を挟んで書く → 挟まなかった場合と**同じ結果**
  - [ ] `close` 後の `write` → 例外。**その後に読んでも長さが増えていない**

### S-03: サーバーの上限は呼び出し元に見えない (実現する要件: R-01)
- 挙動: 1 回の `write` に渡すバイト列が、サーバーが 1 度に受け取れる大きさ
  (`maxWriteSize`) を超えていても書ける。呼び出し元は分割を指示しないし、
  分割されたことを知る手段も要らない
- 境界条件・エラー時:
  - **ちょうど上限**: 1 度の要求で送られる
  - **上限 + 1 バイト**: 2 度に分かれる。結果は 1 本のファイル
  - **上限の数倍**: 何度に分かれても、読み直した中身が渡したものと一致する
  - **分割の途中で失敗**: 例外。`written` は S-05 のとおり
- 受入条件:
  - [ ] `maxWriteSize + 1` バイトを 1 回の `write` で渡す → 読み直すと
        **長さも中身も一致**する
  - [ ] そのとき、サーバーへ送られた Write 要求は **2 回**であり、
        **どちらの長さも `maxWriteSize` 以下**
  - [ ] `maxWriteSize` ちょうどを渡す → Write 要求は **1 回**

### S-04: 失敗は、何が起きたか分かる形で返る (実現する要件: R-01)
- 挙動: サーバーが要求を拒んだとき、`Smb2Exception` を投げる。例外は
  **サーバーが返した NT status を保持**し、`toString()` にその名前が現れる
- 境界条件・エラー時:
  - **権限が無い**: `STATUS_ACCESS_DENIED` を保持した例外
  - **既にある**: `STATUS_OBJECT_NAME_COLLISION` を保持した例外
  - **親が無い**: `STATUS_OBJECT_PATH_NOT_FOUND` を保持した例外
  - **接続が切れた**: `Smb2TimeoutException` か、下位の I/O 例外がそのまま
    出る。どちらも **NT status を持たない**。**status の有無で「サーバーが
    拒んだ」と「答えが返らなかった」を区別できる**
- 受入条件:
  - [ ] 既にある名前への `createNew` の例外が、`STATUS_OBJECT_NAME_COLLISION`
        を保持し、`toString()` にその名前を含む
  - [ ] 権限の無い場所への `createNew` の例外が `STATUS_ACCESS_DENIED` を保持
  - [ ] 答えが返らなかった場合の例外は、**status を持たない**

### S-05: どこまで渡ったかが、後から読める (実現する要件: R-03)
- 挙動: writer は `written` を持つ。値は**サーバーが成功応答を返したバイト数の
  合計**で、成功しても失敗しても読める
- 境界条件・エラー時:
  - **成功したとき**: `written` は渡したバイト列の長さの合計と**等しい**
  - **1 度も書かなかったとき**: 0
  - **途中で失敗したとき**: `0 <= written <= 渡した合計` であり、かつ
    **そのとき共有上に残っているファイルの長さと等しい**
  - **`close` に失敗したとき**: `written` は変わらない
- 受入条件:
  - [ ] 3 つのバイト列を書いて成功 → `written` が **3 つの長さの合計と等しい**
  - [ ] 1 度も書かずに `close` → `written` が **0**
  - [ ] 途中で失敗させる → `written` が**共有上のファイルの長さと等しい**
        (どちらも実測して比べる)

### S-06: 書き込みは、既存の読み取りを 1 行も変えない (実現する要件: R-01)
- 挙動: 書き込みの追加後も、`listDirectory` / `openRead` / `readRange` /
  `readFile` の署名と戻り値は変わらない。既存の呼び出し元は再コンパイルだけで
  動く
- 境界条件・エラー時:
  - 同じ `Smb2Tree` で読みと書きを混ぜても、互いの位置や状態に影響しない
  - 書き込み中に同じ tree で読んでも、読みが待たされる以上のことは起きない
- 受入条件:
  - [ ] 既存のテスト (2026-08-15 時点で 132 件) が**1 件も落ちない**
  - [ ] 同じ tree で「書く → 読む → また書く」を行い、**3 つとも成功する**

## 用語定義

- **`maxWriteSize`**: ネゴシエーションでサーバーが申告する、1 回の Write 要求で
  受け取れる最大バイト数。今のサーバーでは 8MB を申告してくる (2026-08-15 の
  実測)。読み取り側は 1MB に丸めているが、書き込み側をどうするかは design で決める
- **位置**: writer が次に書き始めるファイル内のオフセット。`createNew` の直後は 0
- **渡した合計**: その writer に対する `write` の引数の長さを足したもの
